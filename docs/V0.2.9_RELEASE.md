# DataWeave v0.2.9

**Gradle:** `0.2.9` · **jpackage:** `1.2.9`

## Root cause — “Missing stored credential for connection”

1. **Windows vault persistence:** Passwords were written with `CRED_PERSIST_SESSION`, so Windows Credential Manager entries did not survive application restarts. After restart, the profile existed in SQLite but `CredRead` returned empty.
2. **UX dead-end:** Explorer showed only **Retry** / **Edit connection** with no password field, while the full form lived on the **Connections** tab (non-obvious).

## Fixes

- **Windows:** Store credentials with **`CRED_PERSIST_LOCAL_MACHINE`** so passwords survive reboot/restart (per-user vault).
- **Backend:** Connect/Test return error kind **`missing_credential`** instead of a generic exception string.
- **UI:** **`CredentialRecoveryPanel`** in the explorer (and on vault miss) with host/database/username, masked password, **Save credentials**, **Test**, **Connect**, and **Open Connections**.
- **Edit connection** in explorer opens the correct profile in Connections (not a blank form).
- **Connections** banner when vault has no password for the edited profile.
- **Tests:** `MissingCredentialIntegrationTest`.

## User recovery (after upgrade)

If you still see the error once on an old profile: use the **inline recovery form** in the explorer (or Connections → enter password → **Save** → **Connect**). Re-saving stores the password with the new persistence mode.
