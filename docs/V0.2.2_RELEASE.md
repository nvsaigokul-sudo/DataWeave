# v0.2.2 release (operator steps)

**Gradle:** `0.2.2-SNAPSHOT` · **jpackage file version:** `1.2.2` (Compose mapping).

## Preconditions

- `./gradlew test :desktop:runHeadlessSmoke` green on `main`
- CI matrix green ([ci.yml](../.github/workflows/ci.yml))
- Windows LFS MSI refreshed from a green `windows-latest` job if the packaging recipe changed (see [downloads/README.md](../downloads/README.md))

## Tag and publish (non-destructive)

Does **not** delete or retag v0.2.1.

```bash
git checkout main
git pull origin main
./gradlew test :desktop:runHeadlessSmoke
git tag -a v0.2.2 -m "DataWeave v0.2.2"
git push origin v0.2.2
```

The [release.yml](../.github/workflows/release.yml) workflow runs on `v*` tags, builds Linux/Windows/macOS artifacts, and uploads `SHA256SUMS.txt` to the GitHub Release.

## After Windows build completes

1. Download the workflow’s Windows MSI artifact (or use the release asset).
2. Optionally replace [downloads/windows/DataWeave-Setup.msi](../downloads/windows/DataWeave-Setup.msi) via Git LFS so README + CI-tested bytes match the tag.
3. Update [downloads/windows/SHA256SUMS.txt](../downloads/windows/SHA256SUMS.txt) and run `./scripts/verify-downloads-checksums.sh`.

## Known gap vs CI

`release.yml` still does **not** run Windows install/GUI smoke (that remains in `ci.yml` only). Prefer LFS MSI from `main` until release workflow parity is added.
