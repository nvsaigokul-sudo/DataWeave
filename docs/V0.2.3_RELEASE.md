# DataWeave v0.2.3

**Gradle:** `0.2.3-SNAPSHOT` · **jpackage file version:** `1.2.3`

## Fix

**Windows GUI `HeadlessException` on normal launch (v0.2.2 and earlier):** Spring Boot defaults `spring.main.headless=true`, which sets `java.awt.headless=true` before Compose Desktop calls `application { }`. Packaged `--headless-smoke` and `--gui-smoke` could pass while double-click launch failed; jpackage shows **“Failed to launch JVM”** for the uncaught exception even though Java started (`launch-error.log` has the real stack).

**Change:** `DesktopSession.startForGui()` / `DataWeaveBackendApplication.startForGui()` use `.headless(false)` for the main Compose path. Regression: `SpringHeadlessPropertyTest`.

**Release packaging:** `release.yml` no longer replaces CI-built Windows MSI bytes with stale LFS; release assets use the Windows job output.

## User action

Uninstall old DataWeave, verify **new** MSI SHA256 from [downloads/SHA256SUMS.txt](../downloads/SHA256SUMS.txt) after v0.2.3 publish (not `a9c8ab77…`, `35333f60…`, or cached partial downloads).
